# Policy & Strategy Lab
## Framework Library

**Stage 3 of 12** · Version 1.0 · November 2026

This library documents every tool the Lab uses, and several it deliberately does not teach. Each tool has a card with the same fields: the question it answers, where it comes from, what it needs, what it produces, how to use it, an Indian example, how it is misused, what it cannot tell you, and where it sits in the course.

## How to read the library

**Status.** *Anchor*: taught to independent use on a named day. *Supporting*: demonstrated, used selectively. *Reference*: documented here for participants whose case calls for it; not taught.

**Attribution.** *Originated*: created and published by the named organisation or author. *Developed*: substantially developed by them, with earlier roots. *Popularised*: made widely known by them. *General practice*: widely used, with no single owner. *Lab device*: designed for this course. Attributions marked *verify* rest on secondary sources and must be checked before appearing in teaching material. RAPID is a registered trademark of Bain & Company. Diagrams in the Lab are redrawn in its own visual style rather than copied.

## Problem definition

### 1. Problem, symptom, cause, solution sort

| Field | Content |
|---|---|
| Question it answers | Is what I am calling the problem really the problem? |
| Origin | Lab device, drawing on general problem-solving practice |
| Inputs | Statements you believe about the issue |
| Output | Statements sorted into four categories; a problem statement free of causes and solutions |
| Steps | Write five statements; sort each; rewrite the problem with the causes and solutions removed |
| Indian example | Welfare access: a lack of awareness is a candidate cause, not the problem; the problem is eligible households not receiving benefits |
| Misuses | Treating candidate causes as established; arguing about labels rather than evidence |
| Cannot tell you | Which causes are true |
| Place in the method | Step 1, define |
| Status | Anchor, Day 1 |

### 2. Problem Definition Canvas, with 5W1H and the narrowing ladder

| Field | Content |
|---|---|
| Question it answers | Is the problem precise enough to analyse and act on? |
| Origin | Lab device; 5W1H is general journalistic and quality practice |
| Inputs | The sorted problem; at least two public sources; a decision-maker |
| Output | Nine boxes: group, place, institution, current and desired condition, decision-maker and decision, why it matters, out of scope, measure of success |
| Steps | Climb the ladder (domain, issue, problem, population, place, institution, decision); fill the boxes in order; run the statement through who, what, where, when, why and how do we know |
| Indian example | Madhyapur: households in residential wards hand over mixed waste contrary to the 2016 rules; the Commissioner chooses a compliance strategy |
| Misuses | Filling the current condition with an unsourced number; leaving out of scope empty |
| Cannot tell you | Whether the framing is the right one; record competing framings separately |
| Place in the method | Step 1, define |
| Status | Anchor, Day 2 |

## Structuring

### 3. MECE issue tree, with the hypothesis-led tree

| Field | Content |
|---|---|
| Question it answers | What are the component questions, without overlaps or gaps? |
| Origin | MECE is associated with Barbara Minto's work at McKinsey; issue trees are documented by Conn and McLean. Developed |
| Inputs | A precise problem stated as a question |
| Output | A tree to three levels ending in answerable questions; a sealed working answer |
| Steps | Write the root question; choose one splitting logic (stage, actor, supply and demand, formula); test level one for overlaps and gaps; build down to answerable leaves; write a hypothesis-led version and seal your best answer |
| Indian example | Madhyapur split by the waste chain: home, collection, processing, enforcement |
| Misuses | Mixing splitting logics; leaves that are solutions; a mind map presented as a tree |
| Cannot tell you | Which branches matter most (see 18) or which are true |
| Place in the method | Step 2, disaggregate |
| Status | Anchor, Day 3 |

### 4. Driver tree

| Field | Content |
|---|---|
| Question it answers | How does an outcome break down arithmetically? |
| Origin | General practice in finance and consulting |
| Inputs | An outcome that can be expressed as a product or sum of components |
| Output | A tree of multiplicative or additive drivers |
| Steps | Express the outcome as a formula (for example coverage times uptake times use); find data for each driver; see which driver constrains the outcome |
| Indian example | Girls riding to school equals eligible girls times the share identified, applying, receiving and using |
| Misuses | Treating drivers as independent when they interact |
| Cannot tell you | Why a driver is low |
| Place in the method | Step 2; reused as the indicator tree on Day 19 |
| Status | Supporting, Days 3 and 19 |

## Causes and systems

### 5. Problem tree

| Field | Content |
|---|---|
| Question it answers | Why does the problem exist, at which level? |
| Origin | General practice in development project planning, associated with the logical framework approach |
| Inputs | The core problem; candidate causes |
| Output | Effects above, the core problem in the middle, proximate and structural causes below, each link with a mechanism |
| Steps | Place the core problem; add effects; add proximate causes; add the structural causes behind them; write the mechanism on every link |
| Indian example | Madhyapur: separating seems pointless because crews mix bags (proximate) because the contract pays by weight (structural) |
| Misuses | Single-cause trees; arrows without mechanisms |
| Cannot tell you | Whether any link is true; that needs evidence |
| Place in the method | Step 2 |
| Status | Anchor, Day 4 |

### 6. Five Whys

| Field | Content |
|---|---|
| Question it answers | What lies behind this cause? |
| Origin | Toyota production system (associated with Sakichi Toyoda and Taiichi Ohno). Originated |
| Inputs | A problem or cause |
| Output | One causal chain |
| Steps | Ask why up to five times; check each answer against the problem tree; run a second chain from another starting point |
| Indian example | Households mix waste because they think it gets mixed anyway, because crews tip bags together, because the contract pays by weight |
| Misuses | Stopping where the analyst's beliefs stop; treating one chain as the explanation |
| Cannot tell you | Whether other chains matter more |
| Place in the method | Step 2 |
| Status | Supporting, Day 4 |

### 7. Fishbone diagram

| Field | Content |
|---|---|
| Question it answers | Have we considered causes in every category? |
| Origin | Kaoru Ishikawa, quality management. Originated |
| Inputs | An effect; a set of categories |
| Output | Candidate causes grouped by category |
| Steps | Write the effect at the head; draw five or six category bones; brainstorm causes on each; move promising ones to the problem tree |
| Indian example | Madhyapur: households, collection, contract, processing, enforcement, information |
| Misuses | Treating a brainstorm as evidence; listing without linking |
| Cannot tell you | Which causes matter or how they connect |
| Place in the method | Step 2 |
| Status | Supporting, Day 4 |

### 8. Causal loop diagram

| Field | Content |
|---|---|
| Question it answers | What keeps the problem in place? |
| Origin | System dynamics, from Jay Forrester's work at MIT; popularised by Peter Senge and Donella Meadows. Developed |
| Inputs | Causes from the problem tree |
| Output | One or two loops with polarities, labelled reinforcing or balancing |
| Steps | Pick a variable; trace what it affects until you return to it; mark each link plus or minus; count minus links (odd means balancing) |
| Indian example | Crews mix waste, households see it, stop separating, more mixed waste: a reinforcing loop fed by the contract |
| Misuses | Huge maps nobody can read; chains presented as loops |
| Cannot tell you | The strength of each link or the size of delays |
| Place in the method | Step 2 |
| Status | Anchor, Day 5 |

### 9. Unintended consequences check

| Field | Content |
|---|---|
| Question it answers | How could the obvious fix make things worse? |
| Origin | Lab device, drawing on Robert Merton's analysis of the unanticipated consequences of purposive action (1936) |
| Inputs | The obvious fix; the actors it affects |
| Output | At least two plausible unintended effects, each with a mechanism and who bears it |
| Steps | Write the intended chain; add each actor's likely response; look for responses that feed back on the problem |
| Indian example | Fining households that mix waste raises roadside dumping |
| Misuses | Listing effects without mechanisms; rejecting good policies because side effects exist |
| Cannot tell you | How likely each effect is |
| Place in the method | Steps 2 and 7 |
| Status | Supporting, Days 5 and 16 |

## Context and institutions

### 10. Delivery chain map

| Field | Content |
|---|---|
| Question it answers | Through which people and institutions does policy reach the citizen, and where does it break? |
| Origin | Associated with Michael Barber's delivery work, including the UK Prime Minister's Delivery Unit. Developed (verify source) |
| Inputs | Scheme guidelines; institutional knowledge; audits |
| Output | Five or six links from policy-maker to citizen, with the likely break point marked |
| Steps | List each link; note who is responsible and what they control; ask how you would know each link works; mark the break with evidence |
| Indian example | Union ministry, state department, municipal corporation, ward staff, contractor crews, households: Madhyapur's break is between ward staff and crews |
| Misuses | Charts without evidence of where the chain fails |
| Cannot tell you | Why the link fails; combine with incentives (16) |
| Place in the method | Step 2 |
| Status | Anchor, Day 6 |

### 11. Jurisdiction and money check

| Field | Content |
|---|---|
| Question it answers | Who has the authority to act, and where does the money come from? |
| Origin | Lab device, from the Constitution of India (Seventh, Eleventh and Twelfth Schedules) and budget documents |
| Inputs | The Constitution; scheme guidelines; budget documents and analyses (PRS Legislative Research, Open Budgets India) |
| Output | Legislative authority, administrative control and funding route identified separately, with sources |
| Steps | Find the list entry or schedule item; identify who administers; trace the budget head and the sharing pattern; note the latest allocation with year and source |
| Indian example | Solid waste management: Twelfth Schedule, item 6; public health and sanitation and local government are State List subjects; mission and Finance Commission funding |
| Misuses | Treating the government as one actor; citing a budget figure without year and source |
| Cannot tell you | Whether funds were released and spent well |
| Place in the method | Step 2 |
| Status | Supporting, Day 6 |

### 12. PESTLE

| Field | Content |
|---|---|
| Question it answers | Have we missed a political, economic, social, technological, legal or environmental factor? |
| Origin | Grew from Francis Aguilar's environmental scanning work in the 1960s. General practice |
| Inputs | The issue tree |
| Output | A checked tree with any missing branch added |
| Steps | Ask, for each factor, whether the tree has a branch for it; add a branch only if the factor would change the analysis |
| Indian example | Madhyapur: political (councillors and ward elections) and social (stigma of waste work) |
| Misuses | Writing six paragraphs instead of an argument |
| Cannot tell you | Anything causal |
| Place in the method | Step 2 |
| Status | Supporting, Day 6 (as a checklist) |

### 13. SWOT

| Field | Content |
|---|---|
| Question it answers | What are an organisation's strengths, weaknesses, opportunities and threats? |
| Origin | Contested; often linked to 1960s business-school and research institute work. Do not attribute to a single author |
| Inputs | Knowledge of one organisation |
| Output | A four-box summary |
| When to use it | Only when the client is an organisation assessing its own capacity, such as a municipal corporation weighing whether it can run a new service |
| Misuses | Using it to analyse a problem rather than an organisation; lists without priorities |
| Cannot tell you | Causes, priorities or what to do |
| Status | Reference |

### 14. Porter's Five Forces

| Field | Content |
|---|---|
| Question it answers | How attractive and competitive is an industry? |
| Origin | Michael Porter, Harvard Business Review, 1979. Originated |
| When to use it | Rarely in this course: for regulated markets with private providers, such as private schools or bus operators |
| Misuses | Applying market logic to welfare services |
| Status | Reference |

### 15. McKinsey 7S

| Field | Content |
|---|---|
| Question it answers | Are an organisation's strategy, structure, systems, shared values, style, staff and skills aligned? |
| Origin | Waterman, Peters and Phillips (1980), at McKinsey. Originated |
| When to use it | When the problem is an implementing organisation's capacity, for example a state agency taking on a new mission |
| Misuses | Using it as a checklist without evidence |
| Status | Reference |

## Actors and political economy

### 16. Power-interest map with absent voices

| Field | Content |
|---|---|
| Question it answers | Who shapes the outcome, what do they want, and who is not heard? |
| Origin | The power-interest grid is commonly attributed to Aubrey Mendelow (1991) (verify). The absent-voices quadrant and incentive columns are Lab adaptations |
| Inputs | The delivery chain; actors affected |
| Output | A map with every key actor placed; an incentive matrix (what they want, what the system rewards, likely response) |
| Steps | List actors; rate power and interest; place them; for key actors, write incentives and likely responses; name the absent voices |
| Indian example | Madhyapur: the Commissioner, councillors and contractor manage closely; waste pickers and residents near the landfill are absent voices |
| Misuses | Explaining behaviour by attitudes; managing only the powerful |
| Cannot tell you | How actors will actually behave under a new design; test against evidence |
| Place in the method | Step 2 |
| Status | Anchor, Day 7 |

### 17. Problem-driven political economy analysis

| Field | Content |
|---|---|
| Question it answers | Why do the institutions and incentives around this problem produce the outcomes they do, and what change is feasible? |
| Origin | World Bank good-practice framework (Fritz, Kaiser and Levy, 2009). Developed |
| Inputs | Actor map; history of reform attempts; rules in use |
| Output | Four answers: who gains from the status quo, who would lose and can block, who would gain but is unorganised, what would make change feasible |
| Indian example | Madhyapur's contractor gains from payment by weight and could litigate or slow collection |
| Misuses | Cynicism: treating feasibility as a reason to recommend nothing |
| Cannot tell you | What is desirable; only what is feasible |
| Status | Supporting, Day 7 |

## Prioritisation

### 18. Pruning matrix

| Field | Content |
|---|---|
| Question it answers | Which branches deserve limited research time? |
| Origin | Described by Conn and McLean as pruning the tree. Developed (verify the axes against the book) |
| Inputs | The issue tree |
| Output | Branches rated by size of effect and ability to influence; two or three priorities; reasons for every cut |
| Steps | Rate each branch with a reason; place it on the matrix; choose priorities; check you have not pruned a small group bearing a large harm |
| Indian example | Madhyapur: collection and processing first; national recycling prices pruned to context |
| Misuses | Pruning by convenience; using intervention-ranking tools to rank issues |
| Cannot tell you | Whether the ratings are right; they are hypotheses |
| Place in the method | Step 3 |
| Status | Anchor, Day 8 |

### 19. Pareto reasoning

| Field | Content |
|---|---|
| Question it answers | Does a small share of causes account for most of the effect? |
| Origin | Named after Vilfredo Pareto; popularised in quality management by Joseph Juran |
| Use | As a search strategy: look for concentration, then measure it |
| Misuses | Assuming the split is 80/20; dropping small groups with large harms |
| Status | Supporting, Day 8 |

## Hypotheses

### 20. Hypothesis register and competing hypotheses

| Field | Content |
|---|---|
| Question it answers | What do we believe, and what would prove it wrong? |
| Origin | Hypothesis-driven consulting practice; the discipline of seeking evidence that discriminates between hypotheses comes from Richards Heuer's analysis of competing hypotheses (1999). Developed |
| Inputs | Priority branches |
| Output | Three to five falsifiable hypotheses, each with disconfirming evidence, a rival and a confidence rating |
| Steps | State each as a comparison; write the disconfirming test first; add a rival and the evidence that would distinguish them |
| Indian example | Madhyapur H1: payment by weight leads crews to mix waste; rival: vehicles lack compartments |
| Misuses | Untestable hypotheses; looking only for support |
| Cannot tell you | The answer; it organises the search for one |
| Place in the method | Steps 3 and 4 |
| Status | Anchor, Day 9 |

### 21. Assumption mapping

| Field | Content |
|---|---|
| Question it answers | Which beliefs should we test first? |
| Origin | Design and product practice, popularised in books on testing business ideas (verify) |
| Output | Assumptions placed by importance and evidence; the important and uncertain tested first |
| Misuses | Mapping without then testing |
| Status | Supporting, Day 9 |

## Research and evidence

### 22. Workplan matrix

| Field | Content |
|---|---|
| Question it answers | What analysis, from which source, by when? |
| Origin | Step four of the seven-step process. Developed |
| Inputs | The hypothesis register |
| Output | A row per priority hypothesis: research question, analysis, named source, deadline |
| Steps | Order rows by which analysis could most change the answer; check each source for level, period and access |
| Indian example | Madhyapur H1: compare cities with different payment terms using published contracts and case studies |
| Misuses | Rows that name government data rather than a specific source |
| Status | Anchor, Day 10 |

### 23. Evidence gap map

| Field | Content |
|---|---|
| Question it answers | Where is evidence on interventions and outcomes plentiful, and where is it missing? |
| Origin | The International Initiative for Impact Evaluation (3ie) and others. Developed |
| Use | Consult an existing map for your sector before designing your workplan |
| Status | Reference |

### 24. Source reliability assessment

| Field | Content |
|---|---|
| Question it answers | How far can this source be trusted, for this question? |
| Origin | Lab device, drawing on evidence-assessment practice |
| Inputs | Each source |
| Output | Producer, method, period, level, coverage and limits recorded; a reliability rating with a reason |
| Steps | Ask the five questions: who produced it and why; how; when and for which period; at what level; what it leaves out |
| Indian example | Ward returns are self-reported by staff judged on them: low to medium reliability |
| Misuses | Rating by reputation alone |
| Status | Anchor, Day 11 |

### 25. Disaggregation analysis

| Field | Content |
|---|---|
| Question it answers | Where does the problem concentrate? |
| Origin | General statistical practice |
| Output | Charts or tables by place, group or time, with interpretation and limits |
| Steps | Compute the aggregate; break it down; check denominators, missing data and changes in counting; title each chart with its finding |
| Indian example | Madhyapur's average rose mainly because planned colonies improved; informal settlements barely reported |
| Misuses | Reporting averages; points and per cent confused; causal language from patterns |
| Status | Anchor, Day 12 |

### 26. Comparative case matrix

| Field | Content |
|---|---|
| Question it answers | What can we learn from places that tackled a similar problem? |
| Origin | Comparative policy analysis; the policy transfer literature (Dolowitz and Marsh, 2000) |
| Output | For each comparison place: what was done, what helped, evidence of results, what transfers |
| Indian example | Indore, Pune and Ambikapur's routes to separated collection, each under particular conditions (verify descriptions) |
| Misuses | Copying forms without functions; treating fame as proof |
| Status | Anchor, Day 13 |

### 27. Hypothesis testing matrix, with claim, evidence and warrant

| Field | Content |
|---|---|
| Question it answers | Which explanations survive the evidence? |
| Origin | Heuer's competing hypotheses; Stephen Toulmin's model of argument (1958) |
| Output | Supporting and disconfirming evidence per hypothesis; a verdict (supported, weakened, unresolved) and confidence; the strongest finding as claim, evidence and warrant |
| Indian example | Madhyapur: containers weakened; contract supported with the vehicle rival partly true |
| Misuses | Counting supporting sources; missing warrants |
| Status | Anchor, Day 14 |

## Communication

### 28. Pyramid Principle and SCQA

| Field | Content |
|---|---|
| Question it answers | How do we turn findings into an argument a decision-maker can use? |
| Origin | Barbara Minto, developed at McKinsey. Originated |
| Output | A governing message; three non-overlapping key lines; supporting evidence; an introduction in Situation, Complication, Question, Answer form |
| Steps | Write the answer first; group support into MECE key lines; write the SCQA opening; end with the decision required |
| Indian example | Separation fails mainly at collection, because the contract pays for weight |
| Misuses | Topic headings instead of claims; conclusions buried |
| Status | Anchor, Day 15; used again on Day 19 for argument titles |

## Designing options

### 29. Journey map and How Might We

| Field | Content |
|---|---|
| Question it answers | Where does the citizen's experience break, and what question would open up options there? |
| Origin | Service design and human-centred design practice, popularised by IDEO; How Might We is traced in some accounts to earlier innovation practice at Procter & Gamble (verify) |
| Inputs | Published evidence on people's experience (no primary research in this course) |
| Output | A journey with break points; a How Might We question for each break; options that differ in mechanism |
| Indian example | Madhyapur household: no space for a second bin; unpredictable collection; crews mix the streams |
| Misuses | Journeys invented without evidence; questions that contain a solution |
| Status | Anchor, Day 16 |

## Choosing

### 33. Options appraisal (multi-criteria analysis)

| Field | Content |
|---|---|
| Question it answers | Which option is best against explicit, weighted criteria? |
| Origin | Multi-criteria decision analysis; government manuals such as the UK's multi-criteria analysis manual (verify edition) |
| Inputs | Options and a baseline; evidence for each criterion |
| Output | A matrix of reasoned scores and weights, including distribution; a ranking with its sensitivity |
| Steps | Choose criteria and argue weights; score every option and the baseline with reasons; compute weighted scores; vary weights and assumptions |
| Indian example | Madhyapur: the pickers' partnership ranks first; the baseline second, a warning about weights |
| Misuses | Unexplained scores; hidden weights; treating the score as the decision |
| Status | Anchor, Day 17 |

### 34. Cost per outcome

| Field | Content |
|---|---|
| Question it answers | Roughly what does each unit of improvement cost? |
| Origin | Cost-effectiveness analysis. General practice |
| Steps | Estimate cost and outcome for each option; state the assumption that drives each; round honestly |
| Indian example | Madhyapur option B: about Rs 860 per extra household separating (illustrative) |
| Status | Supporting, Day 17 |

### 35. Strategic triangle

| Field | Content |
|---|---|
| Question it answers | Does the option create public value, command legitimacy and support, and have the capacity to deliver? |
| Origin | Mark Moore, Creating Public Value (1995). Originated |
| Use | The final test of the preferred option; name the weakest leg and strengthen it |
| Status | Supporting, Day 17 |

### 36. HM Treasury Green Book: cost-benefit analysis and the Five Case Model

| Field | Content |
|---|---|
| Question it answers | Is a public spending proposal good value, and is the full case for it made? |
| Origin | HM Treasury guidance on appraisal and evaluation; the Five Case Model sets out strategic, economic, commercial, financial and management cases. Originated (check the current edition) |
| When to use it | For large capital or programme proposals with data to monetise benefits; beyond the scope of four weeks, but a useful checklist for the report |
| Status | Reference |

### 37. Public Service Value model

| Field | Content |
|---|---|
| Question it answers | Is a public agency improving outcomes relative to cost over time? |
| Origin | Accenture; set out by Martin Cole and Greg Parston in Unlocking Public Value (2006). Originated |
| Use | For comparing agencies or years, not for choosing between options in one case |

## Delivery

### 38. Theory of change and logic model

| Field | Content |
|---|---|
| Question it answers | How exactly is the intervention supposed to produce the outcome, and which links are assumptions? |
| Origin | Theory-based evaluation (Carol Weiss, 1995, and the Aspen Institute's work on community initiatives); intended impact paired with theory of change by the Bridgespan Group (Colby, Stone and Carttar, 2004). Logic models are general evaluation practice |
| Output | Inputs, activities, outputs, intermediate and final outcomes, with each link marked evidenced or assumed |
| Indian example | Madhyapur option B: the key assumption is that households will separate more once they see separation respected |
| Misuses | Flowcharts without assumptions |
| Status | Anchor, Day 18 |

### 39. RAPID and RACI

| Field | Content |
|---|---|
| Question it answers | Who decides, who must agree, who does the work? |
| Origin | RAPID: Rogers and Blenko at Bain & Company (2006), a registered trademark. RACI: general project management practice |
| Output | Named roles for the key decision (Recommend, Agree, Perform, Input, Decide) or for activities (Responsible, Accountable, Consulted, Informed) |
| Indian example | Madhyapur: the Commissioner decides, finance and legal must agree, the cooperative and crews perform |
| Misuses | Writing the government; leaving activities without an accountable owner |
| Status | Supporting, Day 18 |

### 40. Strategy Palette and problem-driven iterative adaptation

| Field | Content |
|---|---|
| Question it answers | Should we plan in full or build as we learn? |
| Origin | BCG's Strategy Palette (Reeves, Haanaes and Sinha, 2015): classical, adaptive, visionary, shaping and renewal approaches. Problem-driven iterative adaptation (Andrews, Pritchett and Woolcock, 2017) |
| Use | Plan in full when the context is predictable, capability exists and mistakes are costly; adapt when the context is uncertain and capability must be built |
| Indian example | Madhyapur: a ten-ward pilot reviewed quarterly |
| Status | Supporting, Day 18 |

### 41. Risk register and reference-class forecasting

| Field | Content |
|---|---|
| Question it answers | What could go wrong, how likely is it, and who owns the response? |
| Origin | General practice; reference-class forecasting from Bent Flyvbjerg's work on large projects |
| Output | At least five risks across political, administrative, financial, frontline and distributional types, with likelihood, impact, owner and mitigation |
| Use | Check estimates against what happened to similar efforts elsewhere |
| Status | Supporting, Day 18 |

### 42. Operating model design and capabilities-driven strategy

| Field | Content |
|---|---|
| Question it answers | What organisation, processes and capabilities does a strategy need? |
| Origin | Operating model design is general consulting practice, including Deloitte's government transformation sequence (strategy, design, build, deliver, innovate). Capabilities-driven strategy: Leinwand and Mainardi, The Essential Advantage (2011), at Strategy&, now part of PwC |
| When to use it | When the recommendation requires a new unit or major restructuring |
| Status | Reference |

## Measurement

### 43. Indicator tree with SMART indicators

| Field | Content |
|---|---|
| Question it answers | How would anyone know the recommendation is working? |
| Origin | General practice; SMART criteria are usually traced to George Doran (1981) |
| Output | An outcome at the root, conditions as branches, measurable indicators as leaves, each with type, source, baseline and frequency, and at least one disaggregated |
| Indian example | Madhyapur: households separating by ward type, reported separately for informal settlements |
| Misuses | Output-only indicators; targets without baselines |
| Status | Anchor, Day 19 |

### 44. Output-Outcome Monitoring Framework

| Field | Content |
|---|---|
| Question it answers | How does the Government of India monitor its own schemes' outputs and outcomes? |
| Origin | The Ministry of Finance with NITI Aayog's Development Monitoring and Evaluation Office; from 2026-27 the Outcome Budget is presented as the Output Outcome Monitoring Framework, covering central sector and centrally sponsored schemes above a size threshold (verify current details) |
| Use | Compare your indicators with the official ones for your scheme; note where they measure outputs only |
| Status | Supporting, Day 19 |
